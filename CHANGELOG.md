# Changelog

Changes made in this fork ([mgrTDziedzic/Hospital-Fork](https://github.com/mgrTDziedzic/Hospital-Fork))
relative to the original [Hospital](https://github.com/tomvd/Hospital) by Adamas (tomvd).
Original code is © its author, licensed under GPLv3; modifications are © mgrTDziedzic, also GPLv3.

## 2026-11-19
- Plasteel Surgery: beauty surgeries (Increase Beauty Basic/Mid/Advanced, Decrease Beauty Basic/Mid, Make Beautiful/Hideous/Plain/Pretty/Ugly) now appear in normal play. Their worker only accepts a pawn whose current Beauty degree is in its `AllowedDegrees()`, so they are treated as prepared surgeries like Laryngoplasty: `SurgeryUtility.CanAssignAsIs` accepts a pawn that can be given an allowed degree (`PlasteelCompat.CanPrepareBeauty`; degree 0 means no Beauty trait; the degree must not conflict with the pawn's traits or be disallowed by backstory or pawn kind; gene-sourced Beauty traits are left alone), and `SurgeryUtility.AddSurgeryBill` replaces the Beauty trait with a random allowed degree before choosing the part (`PlasteelCompat.TryPrepareBeauty`); if the worker still offers no part the original trait is restored (`RestoreBeauty`) and the wounds fallback is used. `AllowedDegrees()` and the Beauty trait def are read by reflection / def name as Plasteel does. Pawns the worker already accepts are handled as before. The default blacklist is unchanged. If the API differs, one info line is logged and the preparation is off. Silent and unchanged without the mod.
- Internal: `IncidentHelper.DiscardGeneratedPawn(silent: true)` (used by the debug patient sampler) now discards through `WorldPawns.RemoveAndDiscardPawnViaGC`, so discarded pawns no longer remain in the world pool. The sampler counts a relative as discarded only if it was.
- Internal: the faction list, patient-type roll and spawn-and-injure step of `IncidentWorker_PatientArrives` moved into `IncidentHelper` (`GetPotentialPatientFactions`, `RollPatientType`, `PrepareAndInjure`) so a dev-only debug action in the test mod ("Hospital Debug" -> "Patient distribution sample...", 100 or 500 simulated arrivals with the normal rules, summary in the log) shares the same code. Arrival behaviour is unchanged. `SurgeryUtility.EligibleSurgeries` is split into `PawnStageRejection` and `MapStageRejection` (same checks, same order, same result) so the sampler can report which check rejects which recipe; `IncidentHelper.DiscardGeneratedPawn` takes an optional `silent` flag (vanilla silentlyRemoveReferences) used by the sampler.
- Plasteel Surgery: pawn-generation hints for a forced Laryngoplasty (debug actions only) now generate an adult with the Annoying voice or Creepy breathing trait (`PlasteelCompat.TryApplyHints`, worker detected by type name). No change without the mod.
- Plasteel Surgery: Laryngoplasty patients now appear in normal play. The recipe only fits pawns with Annoying voice or Creepy breathing, so it is treated as a prepared surgery: `SurgeryUtility.CanAssignAsIs` accepts an adult humanlike pawn that can be given one of the traits (`PlasteelCompat.CanPrepareLaryngoplasty`: no conflicting trait, not disallowed by backstory or pawn kind, voice body part present), and `SurgeryUtility.AddSurgeryBill` adds one at random before choosing the part (`PlasteelCompat.TryPrepareLaryngoplasty`); if the worker still offers no part the trait is removed and the wounds fallback is used. Pawns that already have a trait or the botched hediff are handled as before. Silent and unchanged without the mod.

Pawn-generation hints for forced Feminize/Masculinize set the matching gender. No change without the mod.
- Internal: patient generation can be steered by an optional `PatientSpec` (type, wound kind, disease, surgery recipe, ignore-restrictions flag; new `Hospital/PatientSpec.cs`). `IncidentWorker_PatientArrives.TryExecute(parms, spec)` and `IncidentWorker_MassCasualtyEvent.TryExecute(parms, forcedType)` are new public entry points; the normal events call them without a spec and behave as before. `SurgeryUtility.AddRandomSurgeryBill` is split into `EligibleSurgeries` and `AddSurgeryBill`; `DiseaseUtility.AddRandomDisease` takes an optional forced disease. Used by new dev-only debug actions in the test mod (specific wounds / disease / surgery patient, specific mass casualty type).
- Internal (debug actions only): a forced surgery ignores `recipe.AvailableNow` (research) and generates a pawn it fits instead of falling back to wounds: new `SurgeryUtility.CanForceOn` acceptance check (up to 60 attempts, `IncidentHelper.GeneratePawn(faction, recipe)`), optional request hints via new `Compat/PawnGenHints.cs` (first provider: `PlasteelCompat.TryApplyHints`, reflection on `PlasteelSurgery.SurgeryDef`: adult, fixed gender, body type different from the target; silent without the mod, one info line if its API differs). No fitting pawn: on-screen message + log line, nothing generated. Normal arrivals are unchanged.
- Fix: `SurgeryUtility.AddSurgeryBill` picked a random fixed body part from vanilla's empty `appliedOnFixedBodyParts` list for recipes without fixed parts, logging "Getting random element from empty collection" for each surgery patient. The check is now `NullOrEmpty`.
- Fix: patients no longer arrive with Scaria and turn berserk. Vanilla `CureScaria` passed the surgery filters and the mod adds the cured hediff first. New `DiseaseUtility.IsAggressionHediff` (name contains "scaria", hediff class derives from `Hediff_Scaria`, or an aggro mental-state giver) now also drives the disease filter; new `SurgeryUtility.IsAggressionSurgery` keeps such surgeries out of `AddRandomSurgeryBill` and the surgery blacklist picker (`IsBlacklistableSurgery` / `CandidateSurgeries` got an `allowAggressive` parameter) unless the challenge below is on. Aggression diseases stay excluded always.
- New challenge, default off: "Allow aggressive patients" (per-map `HospitalMapComponent.AcceptAggressive`, saved, synced in Multiplayer, needs Accept surgery). A patient may then arrive needing CureScaria, sedated by their faction: new hediff `Hospital_TransportSedation` (Consciousness max 1%, disappears after the sedation time, shows remaining time), added before Scaria (`SurgeryUtility.AddTransportSedation`, new `HospitalDefOf`, new saved `PatientData.Sedated`). Downed patients do not go berserk; when the sedation ends without a cure they do. The arrival letter/message adds a warning. New global setting `SedationHours` (2-24, default 8). New English strings only (other languages fall back to English).
- Added FEATURES.md, an overview of the fork's changes (linked from README). Sections: Additions, Compatibility with other mods, Fixes and adjustments; credits the original author.
- Plasteel Surgery (Continued) compatibility: new maps start with these recipes in the surgery blacklist: Decrease Beauty (Basic/Mid) and the body-type mods (Make Thin/Standard/Hulk/Fat/BB). Masculinize, Feminize and Sex Change stay allowed. Existing maps keep their saved list (`HospitalMapComponent.DefaultRefusedRecipes`).
- Fix: patients are no longer given a surgery that its recipe worker rejects for them (Plasteel Increase Beauty on a Beautiful pawn, Laryngoplasty without the trait, Immunity Boost on a Super-immune pawn, body-type mods for the current body type, an implant the pawn already has, etc.). Vanilla deleted such bills without clearing the pending-surgery flag, so the patient stayed stuck until dismissed. New `SurgeryUtility.CanAssignAsIs` / `IsAsIsRecipe`; the chosen body part is also checked against the worker's valid parts. Body-type mods are never assigned to children.
- Tests: added `PlasteelSurgeryTests` (PS1-PS10).
- Fix a surgery patient leaving right after arrival when Multi-Doctor Surgery is active: its "assign doctors" window opened for the mod-made cure bill, and closing it deleted the bill. Patient bills (cure surgery, administered drugs) are now created directly (`SurgeryUtility.CreatePatientBill`) instead of through `HealthCardUtility.CreateSurgeryBill`, so no other mod's health-tab UI runs on them.
- Tests: added "MultiDoctor" test to `BugFixTests`; test helpers create bills the same way.
- Multi-Doctor Surgery compatibility: when its "(Beta) Fast Operation" is ON and a default surgery team is set, patient surgery bills get that team (lead surgeon plus assistants) instead of a plain single-surgeon bill. Without Fast Operation, or when the lead cannot do the surgery, nothing changes. No window is ever opened. Done by reflection (new `Compat/MultiDoctorCompat.cs`, used by `SurgeryUtility.CreatePatientBill`); if the mod is present but its API differs, one info line is logged and the compat is off for the session. If the Multi-Doctor API differs, one info line (not a warning) says so instead. New `Compat/PlasteelCompat.cs`; Multi-Doctor lookup now runs at startup instead of on the first patient.
- Supported optional mods are listed in one place (`Compat/SupportedMods.cs`), each with one or more package IDs; detection ignores the `_steam` suffix. The startup log line now names the detected package ID.

Fix: surgeries whose name merely contained "gr" (e.g. modded Upgrade/Integrated/Graft) were never assigned; they are now. The two copies of the surgery name filter are merged.

- Tests: tests that need an optional mod are now skipped (not run, nothing logged) when it is not active (`HospitalTest.RequiresMod`; results show SKIP and a skipped count). Plasteel test PS8 moved to `BugFixTests` as AsIs1.

## 2026-11-16
- New: patient drug policies. In Hospital Policies pick a vanilla drug policy for each of five lists: "All patients", "Infection" (immunizable disease not yet immune), "Surgery" (real surgery bill or pending cure), "Injuries" (non-permanent injury or blood loss) and "Scars" (permanent injury). A patient gets the union of every list that applies. Drugs with "Scheduled" ticked in the policy are administered by doctors as "Administer X" medical bills placed at the top of the patient's bill list (checked every 250 ticks). The entry's frequency (counted from the last completed dose, not from a failed attempt), mood limit and joy limit are respected, there is at most one waiting bill per drug, and nothing is added for a patient who would be sent home anyway (same rule as the discharge check, so a scar or blood loss alone never keeps a patient, while a tended but still sick or healing patient keeps getting drugs). Each list has a "Teetotalers too" toggle (defaults: All off, Infection on, Surgery on, Injuries on, Scars off); teetotaler patients skip lists whose toggle is off. Leftover drug bills are removed when the patient leaves. Drugs are billed like any other medical bill. Settings are saved per map and synced in Multiplayer.
- Fix: completing or deleting a medical bill other than the cure surgery (e.g. an administered drug) no longer clears the patient's pending-surgery flag; only the cure recipe does.
- Fix: unfinished "Administer drug" bills no longer keep a patient in the hospital or send them to a surgery bed (new `SurgeryUtility.HasRealSurgeryBills`). Vanilla `ShouldSeekMedicalRest` counts any bill that should be done now, so the discharge check now uses `SurgeryUtility.ShouldSeekMedicalRestIgnoringBills` instead.
- Tests: added `DrugPolicyTests` (Drugs1-17) to the in-game test suite and adjusted a vanilla-compat test to the cure-recipe-only pending flag rule.
- Patients now pick the best hospital bed for their condition instead of the first one built: surgery patients get the highest surgery success chance (bed quality, room cleanliness, light, vitals monitor), patients with a disease they are not yet immune to get the fastest immunity gain, and others get the best tend quality. Beds marked for surgery are still preferred by surgery patients and avoided by the others; on equal stats the nearer bed wins.
- Performance: the hospital map component is cached per map, so the patient check run by every pawn's work search no longer scans all map components.
- Added fork notice and attribution (README, About.xml, this changelog).
- Dropped RimWorld 1.4 and 1.5 support; this fork targets 1.6 (and 1.7).
- 1.6 assembly is now a deterministic Release build; test tooling no longer uses machine-specific paths.
- Fix errors after loading a save that lacks hospital settings (opening hours, refused lists, patients) from an older mod version.
- Fix a possible game freeze when generating a disease or plague patient: attempts are capped, failed hediffs are removed and the patient falls back to wounds; diseases without a lethal severity are no longer picked.
- Fix an arrested patient staying on the hospital roster (they kept being billed and treated as a patient).
- Fix "deaf" surgeries targeting a kidney, and special surgery rules discarding the chosen body part when the pawn lacks the special part.
- Fix infection / lung rot patients arriving healthy with a diagnosis and a bill when no suitable body part exists (they now fall back to wounds).
- Fix interrupted feeding jobs being billed, and a possible error when the food is gone.
- After a failed surgery the patient now stays to recover instead of being sent away; the surgery can be re-added for another attempt.
- Fix a possible game freeze when generating a patient: attempts are capped (20); rejected pawns (androids, non-bleeding) are discarded instead of piling up in the world pawn pool; a faction without pawn kinds is skipped.
- Mass casualty events now respect the faction blacklist and skip androids / non-bleeding pawns; with the plague blacklisted the pandemic type is not chosen. An event with no beds (0 pawns) no longer fires and no longer sends an empty letter; the letter shows the real patient count.
- Fix payment silver: amounts are rounded, a stack of 0 is never created, and large payments are split by the silver stack limit.
- Rename the inverted `includeDismissed` parameter of `PatientUtility.IsPatient` to `activeOnly` (true = only patients not yet discharged); behaviour of every call is unchanged.
- Added an in-game test suite (`Tests/HospitalTests`, a separate dev-only mod that exists only in the repository and is not part of the Hospital mod) covering the fixed bugs; run it with Dev mode -> Debug actions -> "Hospital Tests" (see `Tests/README.md`).
- Fix wound patients arriving without wounds when the wound severity multiplier is small (damage budget is at least 1 and rounded, not truncated).
- Fix an error when a WorkGiverDef without a work type (some mods) is evaluated for a patient.
- New per-map setting "Mass casualties during danger" (default on = unchanged behaviour: mass casualty events ignore manhunters etc.). Switch it off to make mass casualty events wait for a map without aggressive pawns; weather dangers still follow "Allow patients during danger". Translated for French, German and Spanish variants.
- Clarified the log message shown when no disease is eligible for a patient.
- 1.7: added the missing English translation key for the externally-cured condition message.
